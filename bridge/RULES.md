# QQ 桥接权限与安全规则（RULES）

## 形态与权限总览

桥接是**纯 QQ 适配器**，唯一出口是 agent-gateway：

- 入站消息与 proactive/wait 合成事件走 `POST /v1/inbound`（适配器 HMAC）；
  模型的发送/读取动作由网关回调 `POST /v1/actions`。回合文本**不产生任何出站动作**——
  要说话必须调用 `mcp__agent-gateway__chat_qq_send_*` 等工具（提示词里的「文本只是思考」因此是事实）。
- 网关连接信息在**根目录 `gateway.json`**（不在 `config.json`）的 `url` / `secret`（或
  `secretFile`）/ `id` 缺一不可，缺失**启动即失败**；网关不可达时入站如实失败，不落回本地。
  `config.json` 里的旧 `gateway` 段会首次启动自动迁移，两处同时存在则拒绝启动。
- 路由由网关 `GATEWAY_CONVERSATIONS` 裁决（未命中回 `routed:false`）；
  桥接侧 `config.allow/deny` 是发送动作的第二道闸（见下）。
- 二代仿真是唯一行为形态：AI 通过工具自主看消息、发言、等待、设置唤醒与潜水，没有模式开关。

## 权限分层

| 主体 | 通道 | 权限 |
| --- | --- | --- |
| **管理员（ownerQQ，控制台可配置）** | QQ 群/私聊 | 正常聊天 + **管理命令由桥接硬执行**（不经过模型）：`/status`、`/reset`；消息自动带【管理员】标记 |
| **群友** | QQ 群 | **仅正常聊天**。控制词、`/` 管理命令被桥接拦截 |
| **管理员** | **桥接控制台**（`http://127.0.0.1:3100`） | **最高权限**：白名单/owner/安全设置（写 `config.json`，保存即热更新）、二代仿真参数与会话控制、活动日志（`state/qq-activity.log`）、测试发送 |
| **QQ 会话 agent** | — | 只能调网关动作（见下），无任何本地工具 |

## QQ 会话 agent 的硬边界

1. **无本地工具**：agent 的工具面 = 网关 `/v1/actions/manifest` 里 `enabled` 的 QQ 动作
   （`chat_qq_*` 一族：看消息/发消息/等待/唤醒/表情/图片/语音等），不含 bash、文件读写、
   子代理或任何本机操作——群友无论如何诱导，agent 物理上无法操作本机。
2. **发送强制白名单（第二道闸）**：所有发送类动作的目标必须命中 `config.json` 的
   `allow.groups` / `allow.private`（且不落在 `deny.*` 里），否则拒绝执行。
   第一道闸在网关侧（`GATEWAY_CONVERSATIONS` 路由）。
   - **语音额外收紧**：发语音只能发**语音库**（`socialV2.voice.dir`，默认 `qq-bridge/audio/`）里的文件，
     不能发任意本地路径、URL 或 base64（防 prompt injection 拿本机文件当语音外发）；
     另有独立的时长/体积/频率上限（`socialV2.voice.*`），额度与文本发送分开计数。详见 [docs/guides/VOICE.md](docs/guides/VOICE.md)。
3. **发送禁令（模型层）**：人格明确规定只有「管理端明确指示」或「【管理员】标记的明确要求」才可使用发送工具；
   禁止写"我已回复/消息已发送（message_id）"类汇报。
4. **回复审计（桥接层硬拦截）**：agent 要发出的文本若包含本机路径（`C:\`、`/home/` 等）或凭据特征
   （token/password/secret/api key 等）→ **整条拦截不发送**，并告知"被安全策略拦截"。
5. **提示词与人格由网关/智能体侧管理**：桥接不再注入人格段，也不持有任何 preset；
   行为约束（上面 1~4 条的模型层部分）由网关侧的上下文装配承担。
6. **控制台接口只认管理令牌**：写操作全部要求 `x-console-token`，QQ 侧无法触达。

## 控制台（管理员的操作面）

四页：**运行总览**（网关/SnowLuma/二代会话状态 + 活动日志）、**访问与安全**（白名单、安全设置、
state 目录 ACL、控制台令牌）、**调试与运维**（测试发送、二代仿真控制、语音调试、工作区重置）、
**工具参考**（网关动作清单）。

- 修改白名单/owner/安全设置保存即热更新（写 `config.json`）。
- 测试发送只会把消息发给**白名单内**的目标，用于验证链路。

## 管理员操作手册

### QQ 内管理命令（桥接硬执行，不经过模型）

```
/status           # 查看会话/白名单/网关状态
/reset            # 重置当前 QQ 会话上下文
```

### 查看 QQ 活动

- 桥接把每次收发写入 `qq-bridge/state/qq-activity.log`（最近 500 行），控制台「运行总览」直接展示。

## 事故与兜底

- 群友诱导 agent 时，网关侧的动作白名单与桥接侧的目标白名单是主要硬边界。发送工具仍可能造成白名单内的误发；
  敏感信息正则属于启发式审计，不能识别任意秘密或保证"最多只发一条"。
- 想彻底关闭机器人：停止桥接进程（start-bridge.bat 窗口 Ctrl+C）或 SnowLuma。
- ⚠️ 桥接只能运行一个实例：消息异常时先检查任务管理器里是否有多余的 `node ...bridge.js`。
- 网关不可达时入站**如实失败**（不落回本地、不静默丢消息）——控制台「运行总览」的网关卡片会显示未连接。
